# fbfast 0.3.0 — Latency, concurrent queries and documentation

This release targets databases reached over a WAN, VPN or tunnel. A pooled
query now usually answers after one network round trip instead of four to six,
small text BLOBs travel inside their rows again, wire compression works on
every platform, and independent queries can run together with `run_all`. It
also renames the lifecycle methods so that every blocking method has no suffix
and every coroutine ends in `_async` (or is `aclose`).

## Highlights (20 ms round-trip time, Firebird 5.0.3)

| Case | 0.2.1 | 0.3.0 | firebird-driver 2.0.3 |
|---|---:|---:|---:|
| One row by primary key | 91 ms | 22 ms | 67 ms |
| 1,000 rows with a small UTF8 text BLOB | 28.3 s | 0.19 s | 0.22 s |
| 1,000 rows with a small ISO8859_1 text BLOB | 28.8 s | 0.20 s | 0.23 s |
| `LIST()` inside `WITH` | 2.6 s | 0.04 s | 0.09 s |
| 1,000 narrow rows | 134 ms | 49 ms | 111 ms |
| 32 small queries at once, 8 connections | 0.47 s | 0.19 s | 0.43 s |
| 128 small queries at once, 8 connections | 1.84 s | 0.82 s | 1.47 s |
| 100 rows × 20 KiB BLOB, 1 MiB/s, compression on | 10.8 s (not negotiated) | 0.09 s | – |

## Breaking changes

Lifecycle names follow one rule: no suffix blocks, `_async` / `aclose` are coroutines.

| 0.2.x | 0.3.0 |
|---|---|
| `pool.close_sync()` / `await pool.close()` | `pool.close()` / `await pool.aclose()` |
| `pool.warmup_sync()` / `await pool.warmup()` | `pool.warmup()` / `await pool.warmup_async()` |
| `pool.clear_statement_cache_sync()` / `await pool.clear_statement_cache()` | `pool.clear_statement_cache()` / `await pool.clear_statement_cache_async()` |
| `snapshot.close_sync()` / `await snapshot.close()` | `snapshot.close()` / `await snapshot.aclose()` |
| `init_pool_sync()` / `await init_pool()` | `init_pool()` / `await init_pool_async()` |
| `close_pool_sync()` / `await close_pool()` | `close_pool()` / `await close_pool_async()` |
| `pool.snapshot_async()` | `pool.snapshot()` (works with `async with`) |

The old `_sync` names and `snapshot_async()` still work and emit
`DeprecationWarning`; they will be removed in 0.4.0. Names whose meaning flipped
have no alias, but old code fails loudly: `await pool.close()` now raises
`TypeError` because `close()` returns `None`.

Other visible changes:

- **Cleanup after the reply.** Rollback and `ALTER SESSION RESET` run after the
  caller receives a complete result. A failure there no longer raises
  `CleanupError` to that caller; the connection is discarded and the failure is
  counted in `stats()["cleanup_errors"]`.
- **Pre-started transactions.** After a query that read all its rows, the
  session reset also starts the next query's transaction
  (`ready_transaction_timeout`, default 2 s; `None` disables it). Every query
  still gets its own transaction and a reset session. If the link drops within
  that window, the next query on that connection raises
  `DatabaseConnectionError` instead of being replaced transparently.
- **Snapshot deadline.** A snapshot without `timeout=` now uses the new
  `snapshot_timeout` (300 s) for the whole scope instead of `query_timeout`
  (30 s). Each query inside still uses `query_timeout`.
- **Errors.** The exception classes are now defined in Python (`fbfast._errors`,
  exported from `fbfast` as before); `fbfast._native` no longer exports them.
  New: `UsageError` (also `RuntimeError`), `ArgumentError` (also `ValueError`
  and `TypeError`), `ConcurrentUseError` (subclass of `PoolBusyError`, for a
  snapshot or stream used twice at once) and `DatabaseConnectionError`
  (subclass of `QueryError` and `ConnectionError`, SQLSTATE class 08 or a
  refused attach). `QueryTimeoutError` and `PoolTimeoutError` also derive from
  `TimeoutError`. Errors raised in Python carry `phase`, `sqlstate`,
  `native_codes` and `cleanup_errors` like native ones. Existing `except`
  clauses keep working.
- **BLOB streams.** Streams with BLOB columns are batched by decoded bytes
  (`batch_bytes`) instead of one row per batch.
- **UTF8 text BLOBs** are read raw; invalid UTF-8 bytes now raise
  `DataConversionError` from fbfast instead of a server transliteration error.
- **JSON floats.** Large and small magnitudes are written as `1e+20` (was
  `1e20`), following serde_json 1.0.147+. Both are valid JSON numbers.
- **Client loading errors** now include the operating system's reason (for
  example the missing dependency reported by `dlopen`).
- `stats()` gained `wire_roundtrips`, `wire_sent_bytes`, `wire_received_bytes`,
  `deferred_cleanups`, `keepalive_pings`, `reconnects` and `transaction_restarts`.

## Added

- `fbfast.Query` factories (`fetch_all`, `fetch_one`, `fetch_val`, `fetch_json`,
  `fetch_arrow`, `fetch_polars`, `explain`) and `Pool.run_all`, `run_many`,
  `run_all_async`, `run_many_async`: several queries at once, at most
  `concurrency` (≤ `pool_size`) in flight, typed results (`results[query]`),
  group deadline, `fail_fast`, cancellation when leaving the block.
- `FirebirdConfig(diagnostics=True)` with `Pool.diagnostics()`: time and round
  trips per phase of every pool query. `Pool.session_info()`: negotiated
  encryption, compression, wire protocol and inline-BLOB support.
- Options `snapshot_timeout`, `max_inline_blob_size`, `blob_cache_size`,
  `diagnostics` and `ready_transaction_timeout`.
- Public typing helpers: `fbfast.DEFAULT`, `Timeout`, `Params`, `PoolStats`,
  `QueryTrace`, `PhaseTrace`, `SessionInfo`.
- Wire compression on macOS: the official macOS client looked for
  `libz.dylib.1`, which no macOS provides; the runtime now ships a library that
  only re-exports the system zlib under that name.
- CPython 3.15 wheels.
- Documentation: guides for configuration, errors, recipes, performance and
  troubleshooting, a generated API reference, `llms.txt` inside the package and
  at the repository root, `AGENTS.md`, and runnable examples tested in CI.
- License: `MIT OR Apache-2.0` (`LICENSE-MIT`, `LICENSE-APACHE`). The bundled
  Firebird client keeps its IPL/IDPL licenses.

## Performance

- 1 round trip on the critical path for a cached query on a busy connection
  (2 after 2 s idle), down from 4–6; idle connections are pinged in the
  background, which also keeps tunnels and NAT mappings alive.
- UTF8 and ISO8859_1 text BLOBs are opened without a BLOB parameter buffer, so
  Firebird 5.0.3+ inline BLOBs are used (ISO8859_1 is converted locally,
  verified against the server for all 256 bytes). Other text charsets still use
  the server filter.
- Faster conversion to Python: column names created once per result, a direct
  path for 64-bit integers, dates and times built without Python calls,
  `Decimal` from text, reused fetch buffers, and synchronous streams that wait
  on a signal instead of sleeping.
- One request type and one batch planner in the core; SQL is tokenized once per
  query.

## Fixed

- A cancellation or deadline that reached the server between a statement's
  prepare and the start of its execution was ignored, so the query ran to the
  end. The cancel is now repeated every 200 ms while the operation is running.
- Wire compression was never negotiated with the official macOS client (see Added).

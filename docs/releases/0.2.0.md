# fbfast 0.2.0 — Typed query results with Pydantic

Turn Firebird query results into validated application models directly at the
query boundary. Pass `model=Order` to `fetch_one` or `fetch_all` and get an
inferred `Order | None` or `list[Order]`, without manually unpacking dictionaries.

```python
from pydantic import BaseModel

class Order(BaseModel):
    ID: int

order = pool.fetch_one("SELECT ID FROM ORDERS WHERE ID = ?", [42], model=Order)
orders = await pool.fetch_all_async("SELECT ID FROM ORDERS", model=Order)
```

## Added

- Optional Pydantic v2 integration via `fbfast[pydantic]`.
- Typed results across synchronous/asynchronous queries, snapshots, and
  module-level named-pool helpers.
- Model aliases, strictness, custom validators, and normal Pydantic validation
  errors. Empty results remain `None` or `[]`.
- Async validation outside the event loop. Validation follows fetching and is
  outside the query deadline; cancelling an await does not stop a validator
  already running in its thread.
- Static typing checks, regression tests, conversion benchmark, and typed-model
  coverage in the cross-platform wheel CI smoke tests.

## Documentation and maintenance

- Rewritten English README with practical examples, output-format guidance,
  installation details, and measured performance context.
- Retired the obsolete implementation plan; preserved outstanding requirements
  in the roadmap and the original document in Git history.
- Documented build-cache cleanup and ignored macOS metadata. Build artifacts
  remain outside Git.

Existing tuple/dictionary calls retain their behavior and do not require
Pydantic. Streaming does not yet accept `model=`.

## Validation status

Local macOS arm64 checks for 0.2.0 passed: 47 model/packaging
checks, static typing, lint, module boundaries, workflow lint, and bundled-wheel
verification. Real-server checks were blocked locally by sandbox restrictions
on Docker and loopback ports. The release workflow must pass its complete
20-wheel matrix, real-server smokes, sdist checks, and artifact verification
before uploading to PyPI. No publication is claimed by this notes file.

The conversion-only benchmark for 100,000 prepared dictionaries measured median
109.74 ms with `model=`, 111.22 ms with manual `model_validate`, and 102.24 ms
with manual model construction. These local measurements exclude database,
network, decoding, and dictionary allocation; they are not a universal speedup.
